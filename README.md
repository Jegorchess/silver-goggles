# KinoBattleApp — кіно-квіз батл для iOS (у розробці)

Дуель 1 на 1 — з ботом або з іншою людиною онлайн: 7 або 14 питань про кіно (і його історію),
10 секунд на кожне, 4 варіанти, більше очок за швидку відповідь, фінальне питання ×2,
після кожного питання — цікавий факт.

Рішення для MVP (відрізняються від початкової специфікації):
- без категорій і без складності питань — одразу старт раунду;
- без паузи: якщо згорнути застосунок, таймер іде далі;
- без підтримки VoiceOver.

## Що вже є

`KinoBattleApp/Engine/` — ігрова логіка iOS-застосунку без залежності від UI:
- `Question.swift` — формат питання з `questions.json` (з необовʼязковим цікавим фактом `fact`) і перемішування варіантів;
- `QuestionBank.swift` — валідація бази та вибірка питань без повторів з недавніх матчів;
- `Scoring.swift` — правила матчу, формула очок `round(500 + 500·t/10) × k`, визначення переможця;
- `Opponent.swift` — протокол `Opponent`, `BotOpponent` і детермінований генератор для тестів.

`KinoBattleApp/questions.json` — база питань, спільна для застосунку, превʼю й сервера.

`shared/engine.js` — ті самі правила на JS плюс повний перебіг матчу (`Match`). Його використовують
і веб-превʼю (гра з ботом), і сервер (гра з людиною).

`server/` — Node-сервер: онлайн-матчі через WebSocket (код кімнати або випадковий суперник, реванш)
і роздача превʼю. Протокол — у [server/README.md](server/README.md).

## Далі

- iOS: `MatchEngine`, екрани (головний, лобі, матч, результат), онлайн-клієнт до `server/` по WebSocket
  (сервер уже веде матч сам, тож застосунку лишається показувати повідомлення й надсилати відповіді);
- розмістити сервер на хостингу, щоб грати через інтернет, а не лише в одній мережі;
- проєкт Xcode (рушій підключається як локальний пакет).

## Превʼю на Windows (у VS Code)

`preview/index.html` — інтерактивний макет гри в рамці iPhone.

1. `Ctrl+Shift+P` → **Tasks: Run Task** → **Preview: запустити сервер**
   (або вручну: `cd server`, `npm install`, `npm start`).
2. `Ctrl+Shift+P` → **Simple Browser: Show** → `http://localhost:5180/preview/`.

Щоб пограти з людиною на одному компʼютері, відкрий превʼю у двох вікнах (наприклад, Simple Browser
і звичайний браузер): в одному «Створити кімнату», у другому — ввести код. З телефона в тій самій Wi-Fi —
запусти сервер з `HOST=0.0.0.0` (деталі в [server/README.md](server/README.md)).

## Тести

- Swift-рушій (на Windows — через Docker, Swift ставити не треба):
  ```sh
  docker run --rm -v "${PWD}:/src" -w /src swift:6.0 swift test --scratch-path /tmp/build
  ```
  На Mac: `swift test` або відкрити `Package.swift` у Xcode.
- JS-рушій і сервер: `cd server`, `npm test` (або завдання VS Code **Server: тести**).

Якщо змінюєш правила у Swift, онови й `shared/engine.js` — тести в `server/test/engine.test.js`
звіряють ключові значення зі Swift-тестами.

Сам iOS-застосунок збирається й запускається лише на Mac з Xcode.
